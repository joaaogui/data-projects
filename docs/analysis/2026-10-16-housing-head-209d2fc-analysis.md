## Bottom line

The engine is much better than in this morning's reports. 34 of the 71 earlier items are fixed, warm scoring dropped from ~627 ms to ~6–10 ms, and typecheck, lint, tests and build all pass at HEAD. Two big problems remain:

1. **There is no access control.** Anyone who can reach the app can rewrite the shared saved state, spend the Groq key, or take the UI down with a single request. When the app runs locally, they can also feed text to the Cursor agent and start scrapers.
2. **The ranking is skewed in ways the UI hides.** It has false SP corridor penalties, regexes that ignore accented words, a bias toward QuintoAndar listings, and a score that is presented like a 0–100 scale but isn't one.

## 1. Fix first: security and integrity

1. **No authentication on any route except `/api/sync`** **(verified by grep)** (SEC-01, PERS-03, INT-02). An anonymous `text/plain` POST to `/api/preferences` returns 200 and is upserted into the shared Neon preferences row. `POST /api/qa {"action":"clear"}` wipes the whole chat history, and `/api/favorites` flips favorites. `README.md` links `housing.joaog.space` publicly. Whether Vercel Deployment Protection is enabled is not visible from code.
2. **One POST permanently crashes the UI** **(verified)** (SEC-03). `apps/moradia/src/app/api/qa/route.ts:1199` spreads the client-supplied `propertySnapshot` into the stored item without validation. `apps/moradia/src/components/property-chat-drawer.tsx:495` renders `{snap.neighborhood}` as a React child, so a snapshot whose `neighborhood` is an object throws on every render. There is no `error.tsx`/`global-error.tsx`, so the page stays dead across reloads until the item is removed by hand.
3. **Outside text reaches the local Cursor agent** **(verified)** (INT-03, SEC-04).
   - `qa/route.ts:43-44,1206-1226` appends every question, plus the client-controlled snapshot, verbatim to `~/.cursor/Empty/.card-questions-queue.jsonl`.
   - A `watch-card-questions.mjs` process was observed running and reading that file.
   - The local dev server listens on `*:3005` (`lsof`; Next's default hostname is `0.0.0.0`), so any host on the network can deliver text into that agent's input.
   - Whether cross-site browser requests to localhost succeed depends on the browser's local-network protections. That part is not verified.
4. **`/api/scrape/run` launches processes for anyone** (SEC-05, INT-01). It spawns a detached `node` child with arguments taken from the request body, `maxPages` has no upper bound, and the child inherits the full `process.env` with all secrets. This was established from source only. It was deliberately not executed, because it would start a real scraper.
5. **`/api/qa` can drain the Groq key** (SEC-02). The analyst demonstrated a ~2 MB prompt per request, with no rate limit and no size caps. `packages/shared/src/rate-limit.ts` exists but no moradia route imports it.

**Fix direction:**
- One owner credential enforced centrally in a Next 16 `proxy.ts`.
- Zod validation with size caps on every body.
- Run `next dev -H 127.0.0.1`.
- Give the scraper child only the env vars it needs.
- Remove the queue write from the public endpoint, or gate it.

## 2. Ranking correctness

6. **The SP "Efeito Bunker" rule fires on mentions, not on the listing's street** **(verified, `apps/moradia/src/lib/scoring-engine.ts:976-977,1060-1064`)** (SCORE-01). The corridor regex tests `combinedMicroText`, which is description + title + nearby-place names. As a result, 103 of 142 SP flags come only from phrases like "fácil acesso à Av. Santo Amaro" or a nearby "Hospital 9 de Julho". Each flag costs 60–119 points. Example: an Indianópolis listing drops from rank 126 to rank 3277.
7. **Accented words never match** **(verified with an independent probe)** (SCORE-02). Without the `u`/`v` flag, `\b` does not treat accented letters as word characters. `/\b([uú]ltimo andar)\b/i` misses "último andar" but matches "ultimo andar", and `\bsof[aá]\b` misses "sofá". 307 listings would change score if this were fixed.
8. **The furniture classifier misreads negations** (SCORE-03). "Será alugado sem mobília", "não está mobiliado" and "sem cama e sem sofá" are all classified `FULLY_FURNISHED`, a 42-point swing for 4 snapshot listings. Separately, unknown furniture still becomes `UNFURNISHED` and earns the +15 bonus for 996 listings (P-12, still open from the earlier reports).
9. **Budget sliders can contradict themselves** (SCORE-04, SCORE-05).
   - Some slider combinations break the budget invariants, so listings inside the ideal budget are excluded until a reload sanitises the weights.
   - `comfortFloor = max(3500, budgetIdeal - 1000)` (`scoring-engine.ts:3794`) inverts the budget tiers whenever the ideal is below R$ 3,500.
10. **QuintoAndar is favoured** (DATA-01, medium confidence).
   - Inside the same neighbourhoods, QuintoAndar rows score +21.9 points more than other portals' rows.
   - The SP top 50 is 50/50 QuintoAndar.
   - The "Anti-Velharia" preset excludes 51% of ZAP rows versus 17% of QuintoAndar rows.
   - The cause (provider-dependent `condition` and nuance fields) is an inference; the gap is measured.
11. **`totalMonthly` means two different things** (DATA-03). 1,741 QuintoAndar rows (ids `8xxxxxxxx`) include a ~3.9% fee; all other rows do not.
12. **Chat ranks differently from the portal** (SCORE-06, GATE-01, DATA-08). `/api/qa` ranks with `DEFAULT_WEIGHTS` and includes the BSB benchmark rows.
13. **Smaller issues** (SCORE-07..12):
   - The word "cobertura" in boilerplate earns a false penthouse tag.
   - The RJ modernity relaxation becomes a tightening when `minModernityScore` < 56.
   - "portaria virtual"/"biometria" counts as a 24h doorman.
   - `parseCommuteMinutes("1h 20min")` returns 20.

## 3. What the user sees vs what is computed

14. **The score looks like 0–100 but isn't** **(verified with an independent run)** (UX-01). With the saved weights, eligible active listings have median 127.5, max 242.0 and min −43.6, and 75.4% score ≥ 100. The strictest preset, "≥ 85 pts", still keeps 84.1% of listings.
15. **The breakdown chips show 7 of the 10 score components** (UX-02), so the displayed numbers don't add up for 98.8% of eligible listings. The commute term is explained nowhere for 1,107 of them. The engine's own `breakdown` does reconcile with `finalScore`; only the display is incomplete.
16. **The saved filters hide every city's top 20 and 19 of the 20 favorites** (DATA-02). The default sort is by modernity, not by score.
17. **Search is accent-sensitive** (UX-03): "funcionarios" finds 1 listing, "funcionários" finds 130.
18. **500 ineligible active listings are hidden** behind a counter that reads "Exibindo 3790 de 3790" (UX-04).
19. **Map positions look exact but aren't** (UX-05, UX-06, INT-27). Pins and the "a X km do Escritório" distance use made-up or neighbourhood-level coordinates, shown as if exact. "Tempo até o Escritório" is a single constant per neighbourhood.
20. **Photo galleries mix in other apartments** (DATA-06, medium confidence). 63.7% of cached QuintoAndar photos that carry a readable listing id belong to *another* listing, and 17 of the 20 favorites are affected.
21. **Failures are silent nearly everywhere** (UX-14, UX-15, UX-17).
   - There are a11y gaps (UX-20..23): no pressed/selected state, labels given only as placeholders, nested interactive controls, no live region for chat answers.
   - Mobile touch targets are ~18–28 px (UX-12, estimated from code).

## 4. Frontend, sync and persistence

22. **The React Compiler silently skips `MoradiaPortal` and `PropertyMapView`** (FE-01, GATE-03). The causes are the `try/finally` blocks in `moradia-portal.tsx` (lines 2072, 2380, 2566 and 2902, **verified**) and refs read during render in the map component. The lint config enables only `rules-of-hooks` and `exhaustive-deps`, so nothing reports this.
23. **Every card hover re-geocodes and rebuilds every map marker** **(verified)** (FE-02). The map receives `filteredProperties.slice(0, visibleCount)` (`moradia-portal.tsx:5898,6674`), a new array on each render, and its geocode effect depends on `properties`. Ten hovers cost about 20 extra `/api/geocode` POSTs and 1,400 marker rebuilds. The earlier reports' P-51 fixed the original cause, but the symptom is back through this path.
24. **Hydration mismatch** (FE-03, UX-19). The header "Base: dd/mm hh:mm" badge is formatted in the server's time zone (UTC on Vercel), which differs from the browser's.
25. **The whole dataset ships on every load** (FE-06, PERS-05, GATE-08). That is 11.9 MB raw (1.7 MB gzip) in the RSC payload, sent again by `/api/dataset`. That route may exceed Vercel's 4.5 MB function response limit. This is an inference and needs a live check.
26. **Cross-device sync loses edits:**
   - A dataset refresh applies server preferences without the unsaved-edit guard (PERS-01, reproduced with the real component in jsdom).
   - Reverting a change within the 300 ms debounce leaves sync permanently blocked (FE-04; P-40 still open).
   - Saves are whole-document last-write-wins (PERS-02).
   - Failed saves are reported as success (PERS-09).
27. **`focusCardInList` and chat property chips silently wipe all the persisted, shared filters** (FE-05, UX-16).
28. **`/api/sync` cannot ingest the dataset** (PERS-04). Above 1,365 rows a single statement exceeds Postgres's 65,535 bind-parameter limit, and the real 4,407 rows overflow drizzle's stack. There is no transaction and no cleanup of rows that were removed.
29. **Fragile reads** (PERS-06, PERS-07). A torn snapshot file becomes an empty 200 dataset, and one malformed jsonb row breaks the ranking, with no error boundary.
30. **Request-time file writes** (GATE-07, PERS-08, PERS-20, INT-29). On Vercel they go nowhere durable. Locally they dirty tracked files: `photos-cache.json` in the live tree changed during the run.

## 5. Engineering hygiene

- **No CI covers moradia** (GATE-02). The server layer is essentially untested (GATE-04).
- **Oversized client component** (GATE-10, UX-35): `MoradiaPortal` is a single 5,584-line component with 61 `useState` hooks.
- **Runtime-mutated JSON in git** (GATE-09): 17.3 MB is tracked.
- **Hard-coded home path** (GATE-06, FE-18, SEC-14): `/Users/joao.guilherme/...` appears in 4 routes and leaks into UI text and 500 error bodies.
- **The Gemini path is dead code** (INT-05, GATE-15): only Groq is ever called.
- **No README or `.env.example`** (GATE-18): 9 env var names are undocumented.

## 6. What's solid

- **Ordering and arithmetic:** ordering is deterministic, and the engine's breakdown sums exactly to `finalScore`. No NaN or Infinity appears across 6 weight sets × 4,407 rows.
- **Engine robustness:** weight sanitisation is robust, neighbourhood keys are city-prefixed (no collisions), and WeakMap caching gives ~6–10 ms warm scoring.
- **Snapshot:** structurally clean, with 0 duplicate ids or URLs and 0 mojibake, and every favorite/compare/QA key resolves.
- **Photos route:** has a tested https + host allowlist (no SSRF into internal hosts).
- **Type hygiene:** 0 `any`, 0 `ts-ignore`, 0 `eslint-disable`.
- **Build:** needs no env vars.
- **UI:** the photo gallery modal is genuinely accessible.

## 9. Suggested order

1. Auth, validation and binding to localhost (closes section 1).
2. Engine quick fixes: SP rule on the street only, Unicode-aware boundaries, furniture negations, sanitising weights before scoring.
3. Make the score honest in the UI: the full 10-component breakdown, a fixed scale or presets, accent-insensitive search, visible hidden-row counts.
4. A preference-sync state machine (dirty vs queued vs acked), and stop applying preferences from `/api/dataset`.
5. CI for moradia, route tests, the compiler-aware lint rules, and splitting `MoradiaPortal` so the compiler can optimise it.
6. Data: per-provider modernity normalisation, fee-normalised `totalMonthly`, filtering gallery photos by listing id.
