**Housing project review — current working tree, 16 October 2026**

Reviewed `apps/moradia`, its shared-package integration and CI configuration, and the external ingestion worker referenced by the app at `/Users/joao.guilherme/.cursor/Empty`. This review includes existing uncommitted changes. Application source and datasets were not edited by this review; this report is the only repository artifact added.

The main risks are stale listing facts, lost shared-state updates, and treating missing evidence as a known property characteristic. The existing scoring tests pass, but do not exercise most of those paths. P1 means prioritize the next fix; P2 means a concrete functional defect; P3 means a smaller correctness or usability defect.

1. **P1 — Routine synchronization never refreshes details for known listings.** The [worker builds a skip set from saved listing IDs](/Users/joao.guilherme/.cursor/Empty/scripts/scrape-sync-job.ts:541), and the [scraper excludes those IDs from detail fetching](/Users/joao.guilherme/.cursor/Empty/src/imoveis/scrape.ts:735). A search hit alone therefore leaves [the old price and listing timestamp intact](/Users/joao.guilherme/.cursor/Empty/src/imoveis/merge.ts:291), even though the export timestamp advances. The generated fixture retained a rent of 3000 after a subsequent search hit and received a newer export timestamp. Routine sync cannot discover a changed rent or changed details for that existing listing. Add an age-based refresh policy for known IDs and distinguish export time from the time each listing's facts were verified.

2. **P2 — Overlapping preference saves can overwrite a newer selection with an older one.** The [debounced save starts independent whole-state POSTs](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/moradia-portal.tsx:2120). Clearing the timer cannot cancel an already dispatched request. The browser revision guard rejects stale acknowledgements, but the [database update has no revision predicate](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/lib/preferences-store.ts:317). In an isolated callback probe, completing request 2 before request 1 left the browser acknowledging revision 2 while the simulated server held revision 1. Serialize saves and enforce revision checks server-side; do not rely on acknowledgement ordering alone. Full snapshots can also overwrite unrelated changes from another tab or device.

3. **P2 — Failed preference persistence is silently acknowledged or leaves synchronization stuck.** On a database error, [the store returns a local fallback](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/lib/preferences-store.ts:335), the API returns HTTP 200, and [the client ignores `persistedToDb`](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/moradia-portal.tsx:2127). A mocked POST returned `ok: true` and the new filter with `persistedToDb: false`; the next GET returned the old database filter. The client probe acknowledged that nondurable save and cleared its unsaved flag. Separately, an HTTP failure leaves local revision 1 and acknowledged revision 0; [the synchronization guard](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/moradia-portal.tsx:1985) then prevents subsequent GETs, with no retry until another edit or reload. Preserve explicit pending changes, expose save failure, and retry/reconcile them. Distinguish intentional local-only mode from failure of a configured database.

4. **P2 — Concurrent chat mutations lose history.** The [QA handler loads the full history before generating an answer](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/app/api/qa/route.ts:955), then [replaces the entire stored array](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/app/api/qa/route.ts:304). Two simultaneous synthetic `ask` requests both returned 200, but a subsequent GET contained only one question. That was reproduced with the filesystem mocked and the database disabled. The database path has the same unconditional whole-array replacement, so it also lacks concurrency protection. Use per-question records and atomic mutations, or optimistic concurrency with retries. Database save exceptions also need to reach the caller rather than disappear behind a successful response.

5. **P2 — Missing elevator evidence causes hard exclusions.** [Elevator inference](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/lib/scoring-engine.ts:1265) treats no mention plus insufficient provider-specific structural evidence as `hasNoElevator`. Tall-building evidence never exempts QuintoAndar. [Eligibility then eliminates the listing](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/lib/scoring-engine.ts:3262). An otherwise eligible generated eight-floor QuintoAndar property was excluded with no elevator text and became eligible after adding `Elevador`. In the measured snapshot, 791 active listings triggered this rule; only 20 had explicit negative text, and 771 were inferred through missing positive mention and the structural rules. Preserve an unknown state; hard-exclude confirmed absence or provide an explicit filter for unverified elevators.

6. **P2 — Unknown furniture is converted into confirmed unfurnished and rewarded.** The [classifier's fallback](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/lib/scoring-engine.ts:2924) returns `UNFURNISHED` without evidence, and [evaluation rewrites the Boolean and awards the bonus](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/lib/scoring-engine.ts:3155). A generated `furnished: null` property became `furnished: false` and received +15 points. Of 975 raw unknown values in the measured snapshot, 878 took this path. This changes both ranking and the claim shown to the user. Add an unknown tier with an explicit uncertainty treatment instead of awarding the confirmed-unfurnished bonus.

7. **P2 — An inconclusive availability check can reactivate an inactive listing.** The [availability checker returns `isActive: true` for 403, 429 and 5xx](/Users/joao.guilherme/.cursor/Empty/src/imoveis/scrape.ts:786), as well as a missing URL. [Targeted verification includes inactive records](/Users/joao.guilherme/.cursor/Empty/scripts/scrape-sync-job.ts:240), and [every true result becomes a reactivation](/Users/joao.guilherme/.cursor/Empty/scripts/scrape-sync-job.ts:311). Exact-function probes returned active for 403, 429 and 500; the generated merge fixture then changed an inactive record to active and removed its deactivation. Untargeted verification skips already inactive records, so that narrower case does not trigger this defect. Use active/inactive/unknown results and preserve existing status after an inconclusive check.

8. **P2 — The geocoding queue can stop early and mark estimates final.** The [map requests only 32 unfinished points](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/property-map-view.tsx:581) and schedules another pass only when the response itself contains unfinished neighborhood estimates. With 40 generated properties and 32 final results, the exact callback issued one request, left eight properties untouched, and scheduled no next batch. The [finalization condition also overrides `final: false` for street estimates](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/property-map-view.tsx:617). Separately, [failed live lookups are returned as final](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/app/api/geocode/route.ts:205): with both mocked providers offline, the first six addresses became final estimates. Continue while any visible work remains, respect the explicit final flag, and use bounded retries for transient failures.

9. **P2 — Neighborhood filters merge distinct cities.** [Available options are keyed by neighborhood name alone](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/moradia-portal.tsx:2502), and [selection matching omits the city](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/moradia-portal.tsx:562). With multiple cities enabled, selecting Centro can include Centro in BH, RJ and Campinas while the option retains just one city's label; Botafogo also exists in both RJ and Campinas in the snapshot. Store and compare a city-plus-normalized-neighborhood key throughout the option list, selections, counts and ranking lookup.

10. **P2 — An old QA poll can restore deleted messages in the UI.** [Polling accepts any completed response](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/moradia-portal.tsx:2310), independently of [delete and clear mutations](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/moradia-portal.tsx:2362). An exact-callback probe started a GET, completed a successful delete, then released the old GET: the item count went from zero back to one. This is a browser-state race, distinct from the server's concurrent-history overwrite. Discard polls from before the latest mutation or cancel them and refetch afterward.

11. **P2 — Hosted scrape controls depend on a workstation-only worker.** The [route hardcodes the external workspace](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/app/api/scrape/run/route.ts:12), [writes a status file there](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/app/api/scrape/run/route.ts:159), and starts a detached local process. A normal checkout or configured Vercel deployment does not contain that directory; launching fails before the worker starts. Expose the capability only where a configured worker is available, or dispatch to a packaged worker with durable job status. This conclusion is from the deployment and launch code, not a production invocation.

12. **P2 — The photo modal does not manage keyboard focus.** The [gallery declares an `aria-modal` dialog](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/property-photo-showcase.tsx:807), but its [keyboard effect only handles Escape and arrows](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/property-photo-showcase.tsx:763). It does not move focus inside, contain Tab navigation, or restore focus afterward. Keyboard interaction can remain on the page behind the gallery. Use the existing accessible dialog primitive or implement those focus behaviors and verify them in a browser. This finding is source-traced; browser interaction was not run.

13. **P3 — A repeated Neon sync leaves `city` and `sourceSearch` stale.** [Property insertion includes both fields](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/lib/dataset-store.ts:452), but [the conflict-update mapping omits them](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/lib/dataset-store.ts:503). Updating an existing property's city text or source search cannot replace those values through this path. Include them in the update mapping and check insert-then-update behavior. This matters when Neon property reads are enabled.

14. **P3 — Chat history cannot reveal a property excluded by current filters.** The [history navigation helper](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/moradia-portal.tsx:1668) expands and scrolls only cards present in the current filtered list. A saved question about an excluded property produces no visible navigation or explanation. Reveal the property in a separate detail view, adjust the relevant filters, or explain that it is no longer available.

15. **P3 — The 24-hour doorman filter accepts evidence that does not establish 24-hour coverage.** The [feature matcher](/Users/joao.guilherme/dev/nu/data-projects/apps/moradia/src/components/moradia-portal.tsx:370) accepts `portaria virtual` or `biometria` alone. Those terms describe access mechanisms, not operating hours. Require explicit 24-hour evidence or label remote/biometric entry separately. This is a source-level classifier finding; no claim is made about the actual staffing of individual buildings.

If an external gateway does not restrict access, a caller can change shared state or invoke these operations.
